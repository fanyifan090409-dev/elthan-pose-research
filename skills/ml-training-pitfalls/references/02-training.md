# 02 训练篇：配置 / AMP / DDP / 崩溃排查

格式：**症状 → 根因 → 修法 → 出处**。数据集案例为 pose 训练，规则通用。

## 1. 训练进程莫名被杀（oomd）

- 症状：训练跑一半进程消失，GPU 掉 0，dmesg 无 OOM killer 记录。
- 根因：Ubuntu 24.04 systemd-oomd 按内存压力杀进程，触发早于内核 OOM killer；训练机 RAM 大但 workers/cache 吃满时照样触发。
- 修法：`journalctl -u systemd-oomd` 确认；训练机禁用 systemd-oomd，或降 workers、关 cache、加 swap；跑长任务配 watchdog 重启。
- 出处：round1 训练被 oomd 杀（2026-09-26 已修）。

## 2. AMP fp16 下大数值计算溢出崩溃

- 症状：b14 训练 NaN/崩溃，全 fp32 正常；loss 里出现坐标平方类计算。
- 根因：fp16 最大 65504，网格空间坐标（如 128×128 索引）平方/指数直接溢出；AMP 自动缩放只保护乘加，保护不了自定义 loss 里的幂/exp。
- 修法：自定义 loss 中坐标平方、exp 等大数值段显式 `.float()` 转 fp32 再算；梯度缩放器不背这个锅。
- 出处：round6 b14 崩溃 = AMP fp16 网格空间溢出，修复重跑（c2ee539）。

## 3. 自定义 loss 恒 0 / 不下降

- 症状：加了新 loss 项，训练正常但该 loss 打印恒 0，指标无变化。
- 根因：新 loss 没接进计算图——在 `.detach()`/numpy 上计算，或算了没加进总 loss。
- 修法：开训前逐项打印 loss 数值和梯度范数；恒 0 先查计算图连接，再看数据流。
- 出处：解剖先验 loss 接入调试。

## 4. results.csv 固定列号解析错位

- 症状：加新 loss 后，画图/监控脚本读到的 metrics 全错位。
- 根因：按固定列号取列，新列一插入全体偏移。
- 修法：csv.DictReader 按表头名取列（见 scripts/plot_results_csv.py）；列名变化时脚本报错而不是静默错位。
- 出处：round5 多 loss 训练期监控脚本错位。

## 5. 全量开训前不做过拟合自检

- 症状：跑完 100 epoch 发现指标上不去，分不清是数据问题还是代码问题。
- 根因：没有先证明「管道能把小样本拟合到接近满分」。
- 修法：开全量前用 100 图小样本训练，指标接近满分才放行；不过自检的管道一律视为不可信。
- 出处：每轮开训前置门禁。

## 6. 消融轮次混入多个变量

- 症状：A/B 对比出结论，但说不清是哪一处改动造成的。
- 根因：一轮实验同时改了 loss、增强、超参。
- 修法：单轮只改一个变量；多变量改动拆成独立轮次；谱系图记录每轮基线关系。
- 出处：round1-6 谱系（数据轮/LOO 消融/round6 B1+B2'）全靠单变量纪律才可解释。

## 7. 训练与在线服务抢卡

- 症状：训练 OOM 或推理服务延迟抖动，两张卡互相干扰。
- 根因：vLLM/推理服务占着 GPU，训练又挤上去，显存碎片 + 算力争抢。
- 修法：开训前先停同卡服务（vLLM 挂掉腾 GPU1）；训练与在线服务按卡隔离；nvidia-smi 确认空闲再开训。
- 出处：GPU1 vLLM 停机让位训练（常设指令）。

## 8. 数据增强与标签不同步

- 症状：几何增强后 loss 异常高、收敛慢，可视化发现框/关键点漂移。
- 根因：albumentations 只对图像做变换，没配 bbox/keypoint 参数同步变换标签。
- 修法：增强管线配 `bbox_params`/`keypoint_params`；增强后抽样可视化图+标签叠加检查。
- 出处：融合 GitHub yolo-training-template（数据清洗、增强同步标签）。

## 9. seed 不固定不可复现

- 症状：同配置两次训练结果差得超出噪声，复现声明破产。
- 根因：torch/cuda/numpy/worker 全没固定 seed；DDP 多卡还要考虑每卡 seed 偏移。
- 修法：固定 `torch.manual_seed`/`cuda.manual_seed_all`/numpy seed + `deterministic=True`（慢但可复现）；DDP 下 rank 加偏移；seed 写进配置进 git。
- 出处：融合 Pytorch-DDP-Tricks（seed/warmup）。

## 10. 训练中断后无续训能力

- 症状：停电/崩溃后只能从头训，几十小时白费。
- 根因：没开断点续训；或中途改了配置导致 resume 语义失效。
- 修法：resume 依赖 last.pt，改动超参/数据后必须开新轮次而不是 resume；脚本加信号处理落盘 checkpoint。
- 出处：长训轮次的恢复约定。

## 11. 平台期误判为「还能涨」

- 症状：内部 val 在 ±0.005 波动，误读成上升趋势继续加数据。
- 根因：内部 val 噪声级没标定；小波动被当作真实提升。
- 修法：先测同配置重复训练的噪声级（round5-3 0.50532 平台期实测确认）；判决上外部评测集；平台期确认后果断收官换方向。
- 出处：round5-3 平台期确认，数据轮收官。

## 12. 同源帧跨 split 泄露

- 症状：val 指标虚高，外部评测断崖下跌。
- 根因：连续视频帧随机 split，相邻帧同时进 train 和 val；逐视频 stem 拼集时尤其隐蔽。
- 修法：按视频/场景/人分组切 split，禁止组内拆分；或按文件哈希固定 seed 分且核对组边界。
- 出处：PoseTrack 170 视频合并集 split 约定。
