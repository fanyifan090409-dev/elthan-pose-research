# 03 评估篇：口径 / 门禁 / 统计

格式：**症状 → 根因 → 修法 → 出处**。数据集案例为 pose 训练，规则通用。

## 1. 同模型同数据两个「官方」数字差 20+ 点

- 症状：论文表格数字和框架打印的指标对不上，差 20 多个点，无从解释。
- 根因：两套口径——ultralytics 内部 PoseMetrics 与 pycocotools 官方发布口径（2.0.11 keypoints 协议）语义不同：pycoco 把 num_keypoints=0 的 GT 标 ignore（不进 npig、匹配上也不算 tp/fp）、OKS 对这类 GT 用双倍 bbox 距离兜底、maxDets=20。
- 修法：官方发布口径与框架内部口径分开存档（official.json 双段）；论文每个表格注明口径；发布数一律对拍 pycocotools 官方版本。
- 出处：pose-eval-harness 口径实证（2026-09-30），门禁 1 对拍源。

## 2. 自研指标引擎没做对拍

- 症状：自研 mAP/分层引擎结果和官方差 2-3 点，说不清谁对。
- 根因：纯 NumPy 重实现细节（OKS 分母、ignore 语义、分层过滤顺序）与官方不一致。
- 修法：门禁强制对拍：自研引擎 vs pycocotools 官方口径 ≤0.5 点才合入；差异超限先查 ignore 语义。
- 出处：harness 门禁 1（M1 纯 NumPy vs pycoco ≤0.5 点）。

## 3. 合成自检缺失直接跑真实数据

- 症状：新指标实现跑真实数据出数，但无法判断实现对不对。
- 根因：没有构造「答案已知」的桩数据。
- 修法：三道自检先过——GT 角度代预测 → RMSE=0；常数轨迹 → 抖动=0、跳变率=0；分层开启不改变全量匹配（全量 mAP 不因分层而变）。
- 出处：harness 门禁 2、3（tests/test_gates.py）。

## 4. 分层实现改变了匹配逻辑

- 症状：开了分层评测后全量 mAP 变了。
- 根因：分层在匹配前做了过滤/重采样，动摇了匹配集。
- 修法：分层只做「事后分桶统计」，不碰匹配逻辑；门禁断言同模型全量 mAP 开不开分层一致。
- 出处：M1 分层 mAP 实现约定。

## 5. 配对比较的 universe 没对齐

- 症状：两模型配对显著性检验结果诡异，个别样本对不上。
- 根因：两模型预测的图集/单元集不同（有的图只出一个模型的预测），直接配对把不对应的样本拉郎配。
- 修法：先求两模型预测交集 universe，再配对统计；报告里写明配对样本量。
- 出处：harness/statistics.py bootstrap + 相关性约定。

## 6. 指标假 0 先怀疑模型

- 症状：新数据集首跑全指标 0，第一反应「模型不行」。
- 根因：数据链路 bug——标签路径前导零丢失、id 映射错位，GT 全读不到；模型背了数据的锅。
- 修法：指标假 0 先查 GT 加载数、预测文件行数、id 对齐，再查模型；数据链路排查顺序固化。
- 出处：M3 首跑 posemetrics 假 0，修复标签路径后重跑推断。

## 7. 内部 val 小差异误读为有效提升

- 症状：改了个 trick，val 涨了 0.004，宣布有效。
- 根因：内部 val 噪声级约 ±0.005，0.004 在噪声里。
- 修法：先标定噪声级（重复训练/不同 seed）；小差异上外部评测集判决；报告写清差异 vs 噪声级。
- 出处：round5-3 0.50532 平台期实测。

## 8. 内部涨外部跌（只信内部 val）

- 症状：6 组改进内部 val 全涨（0.609-0.613），外部评测集一行没赢 baseline。
- 根因：内部 val 与训练集同域，改进过拟合到域内；外部评测才是泛化判决。
- 修法：内部 val 只做开发信号，结论一律外部评测集定；外部没赢就是没赢，如实写负面结果。
- 出处：round6 B1+B2' 收官判决（CrowdPose 0.53601 / OCHuman 0.39911 未击败 baseline）。

## 9. 时序/角度指标被占位点污染

- 症状：角度 RMSE、抖动指标算出垃圾值，分布明显不对。
- 根因：GT v=0 是 (0,0) 占位（PoseTrack 占 34.4%），pred conf=0 同理；占位点参与角度/轨迹计算。
- 修法：有效性掩码 = GT v>0 且 pred conf>0；全 v=0 空壳 ann 跳过；报告写清有效点占比。
- 出处：harness M2/M3 引擎。

## 10. 统计方法随手选

- 症状：相关性、置信区间结论换了方法就翻案。
- 根因：bootstrap 次数不足、相关性系数（Pearson/Spearman）不按数据分布选、多重比较不校正。
- 修法：bootstrap ≥1000 次；非正态/有序数据用 Spearman；多组比较写校正；统计脚本参数化留档重跑。
- 出处：harness/statistics.py（bootstrap + 相关性）。

## 11. 预测结果不留档

- 症状：报告出了数，事后想重算/对拍发现预测文件被覆盖。
- 根因：save_json 预测、指标 JSON 没作为正式产物归档。
- 修法：每次评测产出落盘：official.json（双口径）+ preds.json + metrics.json + report.md；任何数字可追溯重算。
- 出处：runs/<model>_<dataset>/ 产物约定。

## 12. 论文数字没标口径来源

- 症状：审稿人/导师问「这个 mAP 怎么算的」，答不上来。
- 根因：表格里只有数字，没有口径、工具版本、参数（OKS sigmas、maxDets、数据集 split）。
- 修法：每个表格脚注写明：协议（pycocotools 版本）、参数、评测集、模型权重路径；口径变过的地方写双口径对照。
- 出处：论文 A G1 §5 JSON 契约 + 口径注明铁律。
