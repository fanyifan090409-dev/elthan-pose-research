## 一、NCNN 端侧验证第一轮：三档全通（2026-09-26 21:18，git f349678）

昨日 21:00 首轮对拍 cos≈0.994 但绝对差数百、未过门禁。当晚定位：**对拍工具本身读二进制方式错误**，修复后 pnnx 路线直接通过。完整记录：`lab-notebook/2026-09-26-端侧NCNN验证第一轮.md`。

最终正确导出链：

1. best.pt → best.onnx（ultralytics 8.4.128，opset 12，onnxslim）
2. `scripts/cut_pose_onnx.py` 图手术 → best-raw.onnx：三个裸输出 `[1,64,8400] / [1,7,8400] / [1,51,8400]`，保留 327/353 节点
3. pnnx（inputshape=[1,3,640,640]）→ best_raw.ncnn.param/.bin
4. ncnnoptimize → FP32（39.6MB）/ FP16（19.8MB）
5. INT8：ncnn2table（500 张 val 校准，RGB、mean=0、norm=1/255、method=kl）→ ncnn2int8 → 10.0MB

关键结果（2 图对拍，解码后 vs PyTorch 参考）：

| 档位 | box mean/max | cls mean | kpt mean/max |
|------|--------------|----------|--------------|
| FP32 | 0.058 / 2.84 px | 2e-6 | 0.062 / 4.81 px |
| FP16 | 0.058 / 2.84 px | 2e-6 | 0.062 / 4.81 px |
| INT8 | 4.17 / 73 px | 1.8e-4 | 4.53 / 190 px |

FP32 裸输出 vs ONNXRuntime cos 相似度：box 0.999990 / cls 0.999999 / kpt 0.999983。
训练机 CPU 延迟（Threadripper 7980X 多线程，5 次平均）：FP32 191ms / FP16 200ms（x86 无 fp16 加速）/ INT8 150ms（-21%）。

结论：FP32/FP16 过数值对齐门禁；INT8 均值含 8400 个背景锚点的 DFL 放大噪声，真值锚点误差待 AP 级评测（task #100）。

问题与解决（三坑）：

1. **onnx2ncnn-head .bin pad bug**：手编转换器写出的 .bin 每层权重前多 4 字节零 pad（xxd 确认第一层权重整体偏移 1 float），运行时按顺序读 → 全层权重错位 → 输出全垃圾。弃用。
2. **对拍工具输入读取 bug**：`istreambuf_iterator<char>` 把每个字节当 0-255 的 float 读，输入图整体乱掉，一度误判 pnnx 转换也是坏的。改为按文件大小读字节再 reinterpret 为 float 后直接通过。教训：对拍工具先自证（Swish 单测、ORT 裸输出参考）。
3. **sigmoid 饱和掩盖假象**：cls 通道 logits 全错时 sigmoid 后仍双侧饱和到 0/1 而「完美」，早期「cls 完美 → 主干正确」判断是错的。对比必须做在裸输出上。

产物溯源：`deploy/ncnn/pose-round3/pnnx-raw/`（param/bin/table 六组产物）；对拍工具 `scripts/ncnn_verify_raw.cpp`、`ncnn_diag_raw.cpp`、`pnnx_diag.cpp`、`swish_test.cpp`、`ort_diag_raw.py`；git f349678。

方法：
