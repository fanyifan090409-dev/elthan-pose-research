# pose 训练阶段性总结（2026-09-28）

> 范围：2026-09-26 至 09-28 的 YOLO11s-pose 五轮微调 + 消融 + 过拟合实验。
> 主线数据：官方预训练 → round5-3，COCO val Pose mAP50-95 **0.390 → 0.505（+11.5 点）**，遮挡代理 CrowdPose val **0.474 → 0.536（+6.2 点）**，重度遮挡 OCHuman test **0.272 → 0.399（+12.7 点）**。

|---|---|---|---|---|
| COCO2017 train2017（人物子集） | 53,044 | 官方下载，训练机本地 | round3 起 | 通用域骨架 |

- 验证集恒定 4,924 图（COCO 系 val），保证轮间可比。
- 三基准对拍：COCO val（通用域）、CrowdPose val（遮挡代理）、OCHuman test（重度遮挡）。
- **已知事实**：6 个动作类（sit down/sit up/push down/push up/weights down/weights up）只存在于 round1/2 自采数据；round3-5 训练集全部为 person 单类（7 类头仅 0 号类受训）。

## 2. 训练工具选择

| 选择 | 理由 |
|---|---|
| ultralytics 8.4.128（钉版） | 内置 YOLO11 pose 头 + DDP + AMP + mosaic/close_mosaic + warmup/余弦退火；与端侧导出链（cut→pnnx→NCNN）同源；版本钉住避免行为漂移 |
| conda py310 + torch 2.8.0+cu128 | 5090 Blackwell 支持 |
| 2×RTX 5090 DDP，batch 128（64/卡） | 显存 15.4G/卡，余量充足 |
| tmux + watch_train_vllm.sh 看护 + MLflow | 训练期间自动停 vLLM、结束后自动重启；实验留痕 |
| 统一筛选脚本（screen_crowdpose/ochuman/otp） | 三数据集同口径（bbox 高≥96px、可见点≥8），保证数据可比 |

## 3. 模型选择

- **YOLO11s-pose（9.9M 参数）**：端侧 NCNN 部署链已验证（FP32/FP16 冒烟通过）；s 骨架容量/速度平衡。
- 官方基线（COCO val Pose mAP50-95/mAP50，ultralytics v8.3.85 README）：n 50.0/81.0、s 58.9/86.3、m 64.9/89.4、l 66.1/89.9、x 69.5/91.1。
- 判定：**0.505 落在官方 n 与 s 之间 = s 骨架跑出 n 量级**，属取舍非缺陷——7 类混合头在 COCO 单类评测吃亏、s 容量拿去学遮挡先验；遮挡域 +12.7 点才是产品/论文核心证据。

## 4. 每轮训练细节失误反思

| 轮次 | 失误/现象 | 反思与修复 |
|---|---|---|
| round1（n 模型） | 竖屏自采数据不足；训练被 oomd 杀过一次 | 改走公开数据 + s 模型路线；降 batch 修复 |
| round3 | 前 3 epoch mAP 掉到 0.2 深谷 | 官方 1 类头→我方 7 类头重初始化，属正常现象非 bug；60 epoch 后 0.502 |
| round4 | 误判 CrowdPose 为"12 万张" | 按最大文件名 119999.jpg 推断所致，实际 20,000 张；教训：以文件清单为准 |
| **round5** | **batch 64→128 未考虑 nbs=64 自动缩放，有效 lr 翻倍 0.01→0.02，val 0.492→0.344 崩盘，patience=15 早停** | 修复 lr0=0.005（有效 0.01）+ patience=30；教训：ultralytics 的 lr0 是名义值，改 batch 必须重算有效 lr |
| round5-2 | 从 round5 last.pt 续训 45 epoch → 0.50655 | 有效：复用 92% 旧数据仍 +0.4（OCHuman 域） |
| round5-3 | 续训 30 epoch → 0.50532，零增益 | 结论：数据堆叠已到平台期，需结构性改动 |
| 工程 | nohup + conda 在非交互 ssh 下找不到 conda | 改用 /home/ubuntu/Miniconda3/envs/py310/bin/python 全路径 |
| 工程 | resume 时 last.pt 缺 optimizer 状态自动降级，新建 -2/-3 目录 | 续训必须用完整 last.pt；目录后缀即降级信号 |
| 工程 | 谱系柱图 OCHuman 柱错位画到 round3/round4 组 | 教训：出图必须人工核对数值，不能只看图 |
| 数据 | round3 少量标签坐标越界被 ultralytics 自动忽略 | <0.1%，容忍；筛选脚本已按统一口径挡住大类问题 |

## 5. 训练质量判定与实验证据

- **过拟合实验（2026-09-28）**：从 round3 抽 100 图，官方 yolo11s-pose.pt 起训 100 epoch，close_mosaic=0 → 子集 Pose mAP50 **0.919**、Box mAP50-95 **0.883**。**模型完全能拟合数据 → 管线健康；平台期=数据饱和，非管线缺陷。**
- **消融（checkpoint 差）**：round3 在 OCHuman 上 0.272 = 官方预训练 → **COCO+MPII 对遮挡域零贡献**；+CrowdPose（round4）→ 0.331（+5.9）；+OCHuman+OTP（round5-2）→ 0.395（+6.4）。遮挡增益全部来自 Tier-2 遮挡数据。
- **消融（留一法，2026-09-28 完成）**：去 CrowdPose / 去 OCHuman / 去 OTP 三组，init=round5-2 last.pt，有效 lr 0.005，30 epoch，best 取 fitness 最优 epoch（三基准 Pose mAP50-95，对照 round5-3 全量 0.505/0.536/0.399）。
  - 去 CrowdPose：COCO 0.505 / CrowdPose 0.461（−7.5）/ OCHuman 0.377（−2.2）→ **CrowdPose 价值全在遮挡域，对通用域零贡献**
  - 去 OCHuman：COCO 0.502 / CrowdPose 0.533 / OCHuman 0.331（−6.8）→ **OCHuman 入训在自身域立竿见影；对 COCO 略有拖累（−0.3）**
  - 去 OTP：COCO 0.505 / CrowdPose 0.530 / OCHuman 0.393（均 ±0.6 内）→ **OTP 4,300 图贡献边际，cap 控比合理**
  - **总判定**：三组 Tier-2 数据各司其职——CrowdPose=遮挡泛化、OCHuman=自身域、OTP=边际；COCO 主指标不受任一数据集剔除影响（±0.3），遮挡域指标与数据来源一一对应，数据轮次到此收官。
- **重训价值结论**：val 曲线爬升期重训有价值（round5-2 +0.4）；爬平后（round5-3 +0.0）无价值。数据已喂饱。
