## 二、网络素材抓取流水线（web-batch1）

### 2.1 脚本与产出

脚本落盘于 scripts/fetch_web_data/（文件 mtime：fetch_videos.sh、extract_frames.py 19:12；build_manifest.py 19:34；retry_missing.py 19:37；clean_junk.py 19:38）。

## 三、问题与解决：B站搜索 412

- 现象：fetch.log（96618 字节）大量记录 `Unable to download JSON metadata: HTTP Error 412: Precondition Failed`，bilisearch 检索结果拉取被拒；
- 解决：三轮补漏（retry.log 19:28 → retry2.log 19:35 → retry3.log 19:37），最终在 retry_missing.py 中固化 `--add-headers Referer:https://www.bilibili.com/` 与 `--sleep-requests 5`，对缺失媒体的 .info.json 按 webpage_url 直链补下，成功后写入 .archive 去重；
- 遗留：retry_missing.py 未设每动作上限判断，导致俯卧撑、硬拉分别补到 16、22 个（超出初设 10 个上限）。属内部开发数据，不影响合规边界；下一批次在补漏脚本中补上限检查。

## 五、标注项目初始化

脚本：scripts/cvat_setup_practice.py（20:01）、cvat_consolidate.py（20:01）、cvat_upload_probe.py（20:09）。流程：

1. `docker exec` 进 cvat_server 执行 createsuperuser（用户 ethan，开发凭据内置于脚本常量）；
2. POST /api/projects 创建项目「标注SOP练习-web-batch1」（id=1）；
3. PATCH 项目标签：person 骨架，17 个关键点 sublabel（COCO 顺序：nose → left_eye → right_eye → left_ear → right_ear → left_shoulder → right_shoulder → left_elbow → right_elbow → left_wrist → right_wrist → left_hip → right_hip → left_knee → right_knee → left_ankle → right_ankle），19 条连线；
4. 从深蹲素材按「标准 / 教学 / 错误」三类各选 1 个视频、各抽 20 帧共 60 帧 → practice-frames.zip（7802942 字节）上传，POST /api/tasks 建任务「深蹲60帧-标注练习」（segment_size=60，subset=practice）；
5. cvat_consolidate.py 轮询 tasks/1 至 size=60 → PATCH 挂入项目 1 → 删除临时项目 2；
6. cvat_upload_probe.py：tiny-test.zip（2 帧，323906 字节）经 tus 上传接口 POST /tasks/1/data 探针，psql 查 engine_clientfile 落库、busybox 查 cvat_data 卷落盘路径（诊断用途；任务 1 帧数保持 60，探针帧未残留）。

已确认缺陷（本日遗留）：

- make_labels() 中 19 条连线使用 1 起始索引（最大端点 17），而 CVAT skeleton sublabel 按 0 起始索引（0–16）——连线整体错位一位、17 号端点指向不存在的关键点；
- 修复方案：改用 COCO 标准 0 起始骨架（见 2026-09-08-实验日志.md）。
