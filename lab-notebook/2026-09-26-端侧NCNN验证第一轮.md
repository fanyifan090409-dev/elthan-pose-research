# 2026-09-26 端侧 NCNN 验证第一轮：s 模型三档转换精度全通

## 背景

竖屏数据空窗期（1-2 周）先行验证端侧部署链（三段论：导得出 / 精度不掉 / 跑得动）。
对象：pose-round3 的 YOLO11s-pose best.pt（Pose mAP50-95 0.502）。

## 结论速览

- **切解码出图 + pnnx 转换 = 唯一正确路线**。FP32/FP16 裸输出与 PyTorch 解码结果误差 <0.06px（浮点噪声级）；INT8 box 均值 ~4px（待 AP 级评测确认是否 <2 点）。
- 两条旧路线均废：onnx2ncnn（ncnn-2023 与手编 HEAD 版）输出全错；手编 onnx2ncnn-head 另有 .bin 写入 bug。

## 关键坑（3 个）

1. **onnx2ncnn-head bin pad bug**：手编转换器写出的 .bin 每层权重前有 4 字节零 pad（xxd 确认第一层权重整体偏移 1 float），运行时按顺序读 → 所有层权重错位 → 输出全垃圾。结论：弃用手编 onnx2ncnn。
2. **C++ 对拍工具输入读取 bug**：`istreambuf_iterator<char>` 读二进制把每个字节当 float（0-255），输入图整体乱掉 → 一度误判 pnnx 转换也是坏的。改为按文件大小读字节再 reinterpret 为 float 后，pnnx 模型对拍直接通过。教训：对拍工具本身要先自证（Swish 单测、ORT 裸输出参考）。
3. **sigmoid 饱和掩盖假象**：cls 通道在 logits 全错时 sigmoid 后依然"完美"（双侧饱和到 0/1），早期"cls 完美 → 主干正确"的判断是错的。对比必须做在裸输出上。

## 正确导出链（最终版）

1. best.pt → best.onnx（ultralytics 8.4.128，opset 12，onnxslim）
2. cut_pose_onnx.py 图手术 → best-raw.onnx：三个裸输出 /model.23/Concat_{,1_,2_}_output_0 = [1,64,8400] / [1,7,8400] / [1,51,8400]，保留 327/353 节点
3. pnnx best-raw.onnx inputshape=[1,3,640,640] → best_raw.ncnn.param/.bin（输入 in0，输出 out0/out1/out2）
4. ncnnoptimize → pose-s-raw-opt（FP32, 39.6MB）、pose-s-raw-fp16（19.8MB）
5. INT8：ncnn2table（500 张 val 校准，pixel=RGB, mean=0, norm=1/255, method=kl）→ ncnn2int8 → pose-s-raw-int8（10.0MB）

## 解码（自写，图外）

decode_pose_raw.py：make_anchors + DFL（softmax over 16 bins）+ dist2bbox + kpt decode（(k*2 + (anchor-0.5)) * stride，v=sigmoid）。
公式正确性由 ORT 裸输出验证：ORT 解码 vs PyTorch ref max diff 0.0016。

## 精度数据（2 图对拍，解码后 vs PyTorch ref）

| 档位 | box mean/max | cls mean | kpt mean/max |
|------|--------------|----------|--------------|
| FP32 | 0.058 / 2.84 px | 2e-6 | 0.062 / 4.81 px |
| FP16 | 0.058 / 2.84 px | 2e-6 | 0.062 / 4.81 px |
| INT8 | 4.17 / 73 px | 1.8e-4 | 4.53 / 190 px |

INT8 均值含 8400 个背景锚点的 DFL 放大噪声，真值锚点误差待 AP 级评测。
