## 一、三轮微调：单变量对照（task #21 / #92 / #94 / #97）

方法：固定 val 集（4,927 张，三轮逐文件一致，因 COCO train/val 文件名不相交而天然固定）、60 epochs、imgsz 640、seed 42、optimizer=auto；只改变「数据规模」与「模型尺寸」两个变量，其余超参不变。

| 轮次 | 模型 | 训练集 | 设备 | Box mAP50-95 | Pose mAP50-95 |
|---|---|---|---|---|---|
| R1 | YOLO11n-pose（2.87M） | COCO 15k + MPII，共 29,679 | 单卡 GPU0 | 0.555 | 0.394 |
| R2 | YOLO11n-pose | COCO 50k + MPII，共 64,679 | 双卡 DDP（batch 64/卡） | 0.582（+2.6） | 0.429（+3.4） |
| R3 | YOLO11s-pose（9.4M） | COCO 全量 53,044 + MPII，共 67,723 | 双卡 DDP | 0.616（+3.4） | 0.502（+7.3） |

完整指标：R1 Pose mAP50 0.660；R2 Box/Pose mAP50 0.771 / 0.696；R3 Box/Pose mAP50 0.782 / 0.733，Pose P/R 0.659 / 0.819。

关键结论：

1. 数据仍有效但进入边际递减：人实例 ×3.3 换 Pose mAP50-95 +3.4 点。
2. COCO 近饱和：全量 COCO 有效 person 图仅 53,044 张，50k 抽样已覆盖 94%，故 R3 增益主要来自模型容量。
3. 模型尺寸是当前最大确定性杠杆：n→s 单轮 +7.3 点，已到官方 COCO 基线水平（约 0.50）；距产品目标 ≥0.60 还差约 10 点。剩余杠杆排序：竖屏居家域数据（task #20/#98）> imgsz 640→960 > m 模型（端侧部署优先 s）。

## 三、问题与解决

1. MLflow 上报失败：R2 首启漏带 MLFLOW_TRACKING_URI / MLFLOW_EXPERIMENT_NAME，MLflow 3.x 以 filesystem 后端维护模式拒绝初始化、run 完全不上报；跑到 epoch 3 发现后终止重练（损失约 8 分钟）。教训：训练脚本内联导出环境变量，启动前校验。
2. 权重下载：YOLO11s-pose 权重从 GitHub/HF 双端直连均超时，ModelScope 无对应权重；改用训练机 GitHub 断点续传（`curl -C - -m 1500`，50-100 KB/s，约 8 分钟）成功。
3. 数据构建参数：`build_pose_dataset.py` 默认 `--coco-sample 15000`，建全量集时忘传 0 又生成 15k 版；重跑 `--coco-sample 0` 修正，后续一律显式传参。
4. GPU 资源调度：训练与 vLLM 服务共用双卡，看护脚本参数化（`scripts/watch_train_vllm.sh`），训练结束后自动按原配置重建 vLLM tmux，服务 17:55 恢复，零人工干预。
5. RGB 灯（task #91）收尾：41:00.0 卡 ENE 控制器寄存器读写完全正常、配置与好卡逐字节一致但灯不亮 → 结论为灯条硬件故障，待物理排查（提交 6a0b4b2 / 0fc9c41，详见记忆 project-rgb-lights）。
