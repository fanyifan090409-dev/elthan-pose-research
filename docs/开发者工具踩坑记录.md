## 问题清单（按发现顺序）

### 1. 模拟器启动失败：`fork spawn failed code=EBADF errno=-9 syscall=spawn`

| 项 | 内容 |
|---|---|
| 现象 | 编译子进程（SummerProcess）fork 连续失败 30 次，模拟器起不来 |
| 根因 | macOS 26 系统级兼容问题（Electron 子进程 spawn 失败），非项目代码 |
| 修复 | 完全退出工具 → 重启。一次就好，之后不再复现 |
| 验证 | 日志中 EBADF 计数归零 |

**完全退出工具的正确姿势**（osascript quit 经常无效）：

```bash
osascript -e 'tell application "wechatwebdevtools" to quit'; sleep 3
pgrep -x Electron | xargs kill -TERM
```

### 2. 错误页 `something wrong in electron appservice`（本项目的头号元凶）

| 项 | 内容 |
|---|---|
| 现象 | 模拟器壳子正常、appservice 区域显示白屏错误页，控制台报 `routeTo appLaunch timeout`、`onProxyError /__pageframe__/instanceframe.html` |
| 直接原因 | appservice 对 mainframe 请求返回 HTTP 500，应用代码根本没执行（appservice 控制台日志为空） |
| **根本原因** | `project.config.json` 的 `libVersion: "3.7.6"` —— **这个基础库版本不存在**。3.7 线只有 3.7.12。工具拿不到对应运行时 → appservice 起不来 |
| 修复 | libVersion 改为 `3.7.12` |
| 教训 | 写 libVersion 前先查 `WeappVendor/cfg.json` 的 `libs` 字段；不要凭记忆编版本号。空壳项目（/tmp/minitest）同版本号也失败，反向验证了这一点 |

### 3. 首次 launch 超时、重试必成功（规律，不必惊慌）

每次重编译/重开项目，第一次 launch 常在 10 秒左右报 `routeTo appLaunch timeout`，随后工具自动重试（appservice reload），第二次成功。

- 日志标志：`[appservice] simulator launch success` 只代表容器创建；**`[pageframe] finish load user code` 才是 app 真正跑起来**。
- 判定方法：看到一次 timeout 不要急着重启工具，等 10-20 秒看有没有自动恢复；`finish load user code` + `webview page ready` 出现即成功。

### 4. CLI 报 `IDE service port disabled`

| 项 | 内容 |
|---|---|
| 现象 | `cli open` 失败，提示服务端口未开启 |
| 修复 | 完全退出工具后改设置文件：`security.enableServicePort: true, port: 9420`，再重启 |

### 5. 渲染层不稳定（12:42 错误页复现）

macOS 26 上 GPU 渲染不稳定，关闭后稳定：设置文件 `general.enableGPU: false`。

### 6. 改设置无效？改错了目录

工具曾留下两个数据目录，旧目录 `50a7d921...` 已废弃、活跃目录是 `d1e8765721...`。改错目录会被启动过程覆盖且不生效。用 `find ~/Library/Application\ Support/微信开发者工具 -mmin -5` 找真正的活跃目录。

### 7. screencapture 截屏失败

终端首次无屏幕录制权限时报 `could not create image from display`。授权后可用；截工具窗口前先 `osascript -e 'tell application "wechatwebdevtools" to activate'` 置前，否则截到的是前台应用。

## 诊断方法论（下次遇到问题照这个来）

1. **看日志**：`WeappLog/logs/` 按时间取最新几个文件，搜 `launch success / launch catch / appLaunch timeout / onProxyError / EBADF`。
2. **区分实验**：建一个最小空壳项目（app.js 只有 `App({})`）导入工具。空壳也坏 → 工具/系统问题；空壳好 → 项目问题。**别在项目代码上花时间猜。**
3. **探测服务**：日志里 `simulator launch success, set src http://127.0.0.1:PORT/...` 的端口可以直接 `curl`。返回 500 说明工具内部服务坏了，不是项目问题。
4. **项目侧验证**：appservice 控制台日志文件有内容 = 应用代码执行了；为空 = 卡在工具层。
5. **改配置必先退出工具**，改完再开。
